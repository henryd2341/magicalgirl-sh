# 训练场功能设计

## 目标

将主游戏顶部栏中仅作占位的“训练场”扩展为一个不依赖 AI 的本地战斗功能。训练场包含自由练习与挑战阶梯两种模式，复用现有 Press Turn 战斗系统，同时确保训练内的 HP、MP、状态与道具消耗不会污染正式存档。

首版范围为：

- 自由练习：玩家从现有敌人库自由组合对手。
- 挑战阶梯：5 个按固定顺序解锁的普通关卡。
- 隐藏挑战：完成五关后，通过 DevTools 寻宝与图片谜题解锁 1 个隐藏 Boss 关卡。
- 挑战首次通关奖励以金钱和实用物品为主，具体敌人、奖品、谜题与答案在后续内容设计中确定。

## 非目标

首版不包含：

- 训练专用编队或临时选人。
- 自由练习预设的持久化。
- 每日挑战、周期轮换或连续战斗式爬塔。
- 自由练习奖励或重复挑战奖励。
- 本规格内的具体敌人阵容、奖励数值、谜题图片、题面、题解与标准答案。
- AI 叙事、主线对话或训练战后的 AI 续写。

## 总体体验

点击主游戏顶部栏的“训练场”后，打开单一训练场覆盖层。覆盖层包含“自由练习”和“挑战阶梯”两个页签，共享当前先锋队预览、沙盒规则说明与开战确认。

训练场是主游戏内的模态功能，不新增路由。关闭覆盖层后回到进入前的主游戏画面。

### 自由练习

玩家从现有敌人库（不包括挑战关卡的敌人）中选择一个或多个敌人组成练习阵容：

- 仅展示基础等级不高于主角当前等级的敌人。
- 一场战斗最多配置 4 名敌人。
- 可以选择多个不同敌人，也可以重复选择同一种敌人。
- 使用当前正式编队的先锋成员出战。
- 战斗不消耗正式资源，也不发放经验、金钱或物品。

自由练习页桌面端采用左右分栏：左侧提供敌人搜索、筛选和敌人卡片，右侧展示已选敌人、四个阵容位置、当前先锋与沙盒规则。窄屏改为上下布局。

### 挑战阶梯

挑战模式采用离散关卡，而不是连续作战：

- 5 个普通关卡按固定敌人顺序排列。
- 第一关默认可挑战；通关当前关后解锁下一关。
- 玩家可在关卡之间离开训练场、调整正式编队与整备。
- 每关胜利后回到挑战页，可查看结果或重试。
- 失败、退出和重复通关均无资源惩罚。
- 每个关卡仅在首次胜利时发放一次奖励。
- 重复通关不再发放奖励。

挑战页纵向展示关卡顺序、锁定状态、建议信息、首次奖励摘要和领奖状态。隐藏 Boss 不计入普通五关的顺序与完成度显示。

## 隐藏 Boss 解锁

隐藏 Boss 使用“完成条件 + DevTools 寻宝 + 图片谜题”的发现流程：

1. 五个普通关卡全部通关前，隐藏线索不可交互。
2. 五关全部通关后，挑战页激活一处轻微但持续的异常视觉线索。
3. 玩家点击线索后，打开谜题面板，面板包含答案输入框与提示文字。
4. 提示引导玩家打开浏览器 F12 DevTools，从页面元素或资源信息中找到隐藏图片的下载链接。
5. 玩家下载或查看图片，解开其中谜题并提交答案。
6. 系统对输入做首尾空格清理和英文大小写归一化，再比较配置中的答案校验值。
7. 答错无惩罚且可无限重试；答对后持久化“隐藏关已发现”状态。
8. 解锁后，隐藏 Boss 关卡永久显示，不要求玩家再次解谜。
9. 隐藏 Boss 可重复挑战，但独特首次奖励只发放一次。

该谜题是发现乐趣，不是安全边界。客户端仅保存校验值而不保存直接可读的明文答案，但不承诺抵御主动逆向或存档修改。

谜题图片、下载入口、提示文案、答案校验值与启用状态由独立配置提供。内容未完整配置时，谜题面板显示“谜题尚未开放”，不接受答案提交，也不存在可误解锁的默认答案。

## 架构与职责

### UI 层

新增 `src/ui/training/` 功能目录：

- `TrainingGroundOverlay.vue`：模态框外壳、双页签、关闭与焦点管理。
- `FreeTrainingPanel.vue`：敌人搜索、等级过滤与最多 4 名敌人的临时阵容。
- `ChallengeLadderPanel.vue`：普通关卡、解锁状态、奖励状态和隐藏线索。
- `TrainingBattleConfirm.vue`：敌方阵容、当前先锋和无消耗规则确认。
- `HiddenChallengePuzzle.vue`：DevTools 提示、答案输入与解锁反馈。

`GameTopBar.vue` 新增 `openTrainingGround` 事件，桌面按钮和移动端菜单使用相同事件。`MainGameView.vue` 仅负责挂载覆盖层及协调打开/关闭，不承载训练规则。

### Store 层

新增 `trainingStore.ts`，负责：

- 覆盖层是否显示及当前页签。
- 自由练习搜索条件和临时敌方阵容。
- 当前选中的挑战关卡与确认状态。
- 训练结果展示。
- 调用训练领域服务启动和结束战斗。

Store 不直接发放奖励，不直接修改持久化进度，也不复制战斗公式。

### Engine 层

新增训练领域服务，负责：

- 校验当前会话是否允许进入训练场。
- 从正式变量、背包和当前先锋创建临时战斗副本。
- 验证自由练习阵容的等级与人数限制。
- 以明确的训练来源启动现有战斗系统。
- 在胜利、失败或主动退出后销毁临时副本。
- 处理挑战顺序解锁、首次通关与奖励幂等写回。
- 校验隐藏谜题答案并记录发现状态。

训练来源至少区分：

- `training/free`
- `training/challenge`

现有主线战斗来源保持不变。战斗覆盖层根据来源显示“退出训练”操作，并阻止训练战进入主线战后叙事流程。音频层继续使用已有的 `training` 和 `tower` 战斗音乐映射，退出后恢复进入训练前的场景音乐。

### 会话状态机

`POST_COMBAT_READY` 保持“主线战斗摘要与常规奖励已经结算，等待 AI 续写”的单一语义，不泛化为所有战斗的结束状态。主线战斗继续严格执行：

```text
IDLE / GENERATING
  → COMBAT_PENDING
  → IN_COMBAT
  → POST_COMBAT_READY
  → GENERATING
  → IDLE
```

训练战只允许从稳定的 `IDLE` 进入，复用遭遇暂存和战斗运行状态，但采用显式的非叙事收束分支：

```text
正常结束：IDLE → COMBAT_PENDING → IN_COMBAT → IDLE
开战前取消：COMBAT_PENDING → IDLE
战斗中退出：IN_COMBAT → IDLE
```

训练战不得先进入 `POST_COMBAT_READY` 再立即重置，因为该过程会短暂触发战后叙事面板、聊天摘要、常规奖励或错误的运行时快照。

FSM 新增两个受严格守卫的领域事件：

- `COMPLETE_TRAINING_COMBAT`：仅允许从 `IN_COMBAT` 调用；要求来源为 `training/free` 或 `training/challenge`，且战斗已进入 `RESULT`。自由练习销毁临时状态后进入 `IDLE`；挑战模式先完成幂等首通写回，再销毁临时状态并进入 `IDLE`。写回失败时保持在战斗结果画面，不提前改变会话状态，允许玩家重试。
- `ABORT_TRAINING_COMBAT`：仅允许从 `IN_COMBAT` 调用；要求来源为训练战。它不要求战斗产生胜负结果，确认后清除临时战斗与训练检查点并进入 `IDLE`，不生成摘要、不结算奖励、不更新挑战进度。

开战前取消继续使用受守卫的待战取消事件，只允许 `COMBAT_PENDING → IDLE`，并清除对应的训练暂存数据。Vue 组件不得通过无条件 `resetToIdle()` 实现训练退出；所有退出和收束均通过 FSM 事件完成。首版不新增 `TRAINING_PENDING` 或 `IN_TRAINING` 等训练专用会话状态，战斗来源字段负责选择结算策略。

### 内容配置

新增数据驱动的训练目录配置，普通与隐藏关卡至少包含：

- 稳定关卡 ID。
- 显示顺序与名称。
- 敌方阵容。
- 前置关卡 ID。
- 首次奖励。
- 是否隐藏。
- 内容是否启用。

谜题配置至少包含：

- 是否启用。
- DevTools 提示文案。
- 隐藏图片资源入口。
- 答案校验值与归一化规则版本。

具体内容不写入 Vue 组件。后续新增关卡或替换谜题不应要求修改界面流程。

## 数据与持久化

正式存档只新增必要的训练进度：

- 已通关的普通关卡 ID 集合。
- 已领取首次奖励的关卡 ID 集合。
- 隐藏关是否已发现。
- 隐藏 Boss 是否已通关及领取首次奖励。

通关状态与领奖状态必须分开保存，以便奖励写回失败时恢复。自由练习阵容、搜索条件、覆盖层页签、临时 HP/MP/状态和训练内背包数量不持久化。

挑战首次胜利的写回必须幂等：

1. 验证关卡已解锁且尚未领取奖励。
2. 在同一受控操作中写入通关状态、下一关可用状态所需的数据和奖励。
3. 仅在奖励写入成功后记录已领奖。
4. 重试同一结果时不得重复增加金钱或物品。

若当前持久化接口无法提供真正事务，服务应使用已有检查点或幂等键实现等价的可恢复行为。

## 战斗生命周期

1. 玩家配置自由练习或选择已解锁的挑战关卡。
2. 系统验证主游戏处于稳定空闲状态，主角变量、先锋编队和敌人内容均有效。
3. 系统复制正式先锋战斗数据及正式背包，创建临时训练会话。
4. 系统以训练来源依次进入现有 `COMBAT_PENDING` 与 `IN_COMBAT`，并展示现有战斗覆盖层。
5. 战斗中的 HP、MP、状态、道具消耗只修改临时副本。
6. 胜利或失败进入战斗 `RESULT` 后，由 `COMPLETE_TRAINING_COMBAT` 收束；自由练习只销毁临时副本，挑战胜利先尝试首次通关与奖励写回。
7. 玩家在战斗未决时确认“退出训练”，由 `ABORT_TRAINING_COMBAT` 销毁临时副本。
8. 两种收束均直接从 `IN_COMBAT` 返回 `IDLE`，不经过 `POST_COMBAT_READY`，也不产生主线战斗摘要或 AI 续写。
9. 玩家返回训练场进入战斗前的页签和配置上下文。

训练战在刷新或页面关闭后不得恢复临时消耗。恢复逻辑应清除未完成的训练会话，并返回训练场外的稳定正式状态；正式主线战斗的现有刷新恢复行为不变。

## 入口守卫与异常处理

以下状态禁止进入训练场：

- AI 或故事回合正在生成。
- 存在待处理的主线战斗。
- 已处于任何战斗中。
- 主线战后结算尚未完成。
- 会话处于错误恢复状态。

入口显示禁用原因，不静默失败。

其他异常规则：

- 主角变量、先锋或敌人内容缺失时不创建训练会话，保留当前配置并显示可恢复错误。
- 自由练习阵容为空、超过 4 名或包含高于主角等级的敌人时，开战按钮禁用；领域服务再次验证相同约束。
- 锁定关卡不能通过 UI、Store 或直接服务调用启动。
- 奖励写回失败时不得将关卡标为已领奖，并允许安全重试。
- 谜题内容未配置完整时不得解锁隐藏关。
- Escape 可关闭配置覆盖层；训练战中必须通过明确的“退出训练”确认，避免误退。

## 可访问性与响应式

- 模态框打开时将焦点移入，关闭时将焦点还给训练场入口。
- 焦点被约束在模态框中；所有操作均可通过键盘完成。
- 页签、锁定状态、已通关、已领奖和错误提示提供可被辅助技术读取的语义。
- 颜色不是表达锁定、完成或错误状态的唯一方式。
- 桌面自由练习使用左右分栏；移动端改为上下布局，已选阵容与开战按钮保持易于到达。
- 训练覆盖层遵循现有主题变量，不引入只适用于单一主题的硬编码配色。

## 测试策略

### Engine 单元测试

- 按主角等级过滤敌人。
- 阵容为空、超过 4 名及高等级敌人的拒绝行为。
- 正式状态与训练副本隔离。
- 胜利、失败、退出和刷新时销毁训练副本。
- 主线战斗保持 `IN_COMBAT → POST_COMBAT_READY`，训练结束和退出严格使用 `IN_COMBAT → IDLE`。
- 非训练来源不能调用训练完成或训练退出事件，训练来源不能通过主线战后结算进入 `POST_COMBAT_READY`。
- 五关顺序解锁与锁定关拒绝。
- 首次奖励写回、重复结果幂等及失败恢复。
- 五关完成前后隐藏线索条件。
- 谜题输入归一化、正确答案、错误答案和未配置状态。

### Store 单元测试

- 覆盖层、页签、搜索和敌方阵容状态。
- 顶栏入口守卫及禁用原因。
- 训练启动、结果返回与配置保留。
- 挑战通关及隐藏发现状态的同步。

### UI 单元测试

- 桌面与移动端训练入口发出相同事件。
- 敌人搜索、等级限制、添加、移除与四人上限反馈。
- 关卡的可用、锁定、通关与领奖状态。
- DevTools 提示、谜题输入、未配置及错误反馈。
- 模态框焦点约束、焦点恢复与键盘操作。

### 集成测试

- 从顶栏进入自由练习、完成或退出战斗并返回原页签。
- 训练内 HP、MP、状态和道具变化不进入正式存档。
- 逐关完成五关，激活谜题线索，正确解锁隐藏 Boss。
- 刷新后挑战进度与隐藏发现状态保留，训练临时状态不保留。
- 首次奖励只写入一次，失败后可重试且不会重复发放。
- 现有主线 `trigger_battle`、战后叙事与战斗刷新恢复行为不变。

### E2E 冒烟测试

- 完成一次自由练习，确认正式资源不变。
- 完成一次挑战首通，确认正式资源消耗不变、奖励与进度正确写入。

## 验收标准

- 顶栏桌面与移动端入口都能打开训练场覆盖层。
- 自由练习仅允许选择主角等级以内的敌人，最多 4 名，并使用当前先锋队。
- 自由练习胜败或退出后均无正式消耗、无奖励。
- 五个普通挑战按固定顺序逐关解锁。
- 挑战胜败或退出后均无正式消耗。
- 每关仅首次胜利发放一次金钱与实用物品奖励。
- 完成五关后才激活隐藏线索；只有谜题答案正确才持久化解锁隐藏 Boss。
- 隐藏 Boss 可重复挑战，但首次奖励只发放一次。
- 未完成的训练战在刷新后不会污染正式存档。
- 训练战使用训练 BGM，不触发主线战后 AI 叙事。
- 训练胜败与主动退出均通过受守卫的 FSM 事件返回 `IDLE`，不会短暂进入 `POST_COMBAT_READY`。
- 现有主线战斗、存档恢复和背包消耗流程通过回归测试。

## 后续内容设计接口

实现前或实现过程中可以使用占位关卡验证机制，但正式发布前必须另行批准并补齐：

- 5 个普通关卡的敌方阵容、关卡名与难度梯度。
- 各关首次金钱与实用物品奖励。
- 隐藏 Boss 的敌方定义与独特首次奖励。
- 谜题图片、题面、提示、题解、标准答案和校验值。

这些内容通过训练目录配置接入，不改变本规格定义的交互、生命周期与持久化边界。
