# 挑战模式敌人与 Boss AI 设计

**日期：** 2026-07-13  
**更新：** 2026-07-14<br>
**范围：** 五个正常挑战、一个隐藏双 Boss 战、敌人专属技能、Boss AI 框架、首次通关奖励与悬浮战斗播报窗<br>
**依赖：** 已实现的训练场挑战目录、训练战沙盒、Press Turn 战斗与训练进度持久化

## 1. 设计目标

挑战模式采用固定关卡顺序，共五个正常挑战和一个通过谜题永久解锁的隐藏挑战。五个正常挑战构成递进式考核：

1. 弱点与 Press Turn 管理。
2. 目标优先级与随从控制。
3. 增益、减益、异常状态与解除。
4. 行动规律识别与条件反制。
5. 多阶段综合战与资源规划。

隐藏挑战综合上述能力，并将重点转向稳定输出、行动规划、公开戒律、同步击破和长线资源管理。其难度规格对标经典终局超级 Boss：规则严厉、信息可观察、失败原因可复盘。

设计遵循以下原则：

- 正常挑战的机制通过技能名、状态、动作和战斗日志暗示，不直接给出完整题解。
- 队伍构筑采用软性检验，每关至少保留两种可靠解法。
- Boss 使用固定数值，不随玩家等级动态缩放。
- Boss 专属技能不消耗 MP；技能频率由阶段、冷却和决策树控制。
- 挑战战斗不发放经验值，首次通关奖励金钱和实用物品。

建议玩家等级依次为 `20 / 35 / 50 / 70 / 90 / 99`。目标通关率依次为 `70% / 70% / 50% / 50% / 30% / 5%–10%`，统计对象为建议等级、合理装备且理解机制的模拟队伍。

## 3. Boss AI 混合架构

普通故事敌人继续使用现有 `enemyUtility.ts`。配置了 `bossProfileId` 的敌人进入 Boss AI 框架。

### 3.1 组成

- **Boss Orchestrator：** 处理阶段、强制行动、DPS 检定、狂暴和一次性事件。
- **Mechanic Module：** 保存并更新每场战斗的专属状态，例如回声档案、玩偶部件和双 Boss 复活。
- **Counter Rules：** 判断公开戒律是否触发，并登记对应反击。
- **Boss Utility Profile：** 为常规技能和目标计算专属效用分数。
- **Battle Memory：** 保存回合历史、累计异常抗性、检定结果和已触发事件。
- **Battle Log Signals：** 为所有可推理机制生成技能、状态或日志证据。

敌人内容增加可选字段：

```ts
bossProfileId?: string;
```

`skills.jsonl` 只描述技能结算数据。阶段可用性、冷却、反击条件和效用权重由代码侧 Boss Profile 描述，避免将 JSONL 扩张为脚本语言。

### 3.2 决策优先级

1. 战斗胜负检查，以及已经到期的硬性 DPS/最终处决检查。
2. 强制复活。
3. 阶段转换和一次性事件。
4. 已登记的戒律反击。
5. 非致命 DPS 检定的开启、成功和失败行动。
6. 恢复、解除和召唤等紧急节点。
7. Boss 专属决策树。
8. 专属效用系统选择常规技能与目标。

强制行动不进入效用竞争。常规效用维度包括预期伤害、击杀概率、目标状态、己方生存、连携准备、Press Turn 收益、DPS 窗口、冷却和少量随机扰动。

### 3.3 领域事件与状态

Boss 框架响应以下领域事件：

1. `battle_started`
2. `round_started`
3. `action_resolved`
4. `damage_applied`
5. `status_applied`
6. `participant_down`
7. `before_enemy_action`
8. `round_ended`

Mechanic Module 只更新纯数据状态；Orchestrator 生成 `BossActionIntent`，再交给现有 `battleResolver` 统一结算。

`BattleSnapshot` 保存可序列化的 Boss 运行状态：Profile ID、阶段、回合、冷却、待执行反击、DPS 窗口、回声历史、玩偶部件、异常抗性、复活标记和最终倒计时。决策函数不进入快照，通过 Profile Registry 恢复。

所有随机目标、异常选择和效用扰动使用注入式 RNG。正式战斗使用随机种子，测试与模拟器使用固定种子。

## 4. 第一关：熔核幻蛇

**敌人：** `100`  
**建议等级：** 20  
**编队：** 单体 Boss  
**时间压力：** 无狂暴

熔核幻蛇由熔岩幻蛇强化而来，通过两个公开形态教授连续弱点利用。

### 4.1 熔核形态

- 弱冰、耐火。
- 使用火焰单体、群体技能与燃烧。
- 被冰弱点命中后强制转为蒸汽形态。

### 4.2 蒸汽形态

- 弱雷、冰无效，受到火属性攻击时恢复少量 HP。
- 使用致盲、敏捷下降与低伤害群攻。
- 被雷弱点命中后回到熔核形态，并获得一回合防御下降。

理想循环为“冰击破 → 雷击破 → 利用防御下降输出”。缺少雷属性时，仍可利用冰弱点、减益和非雷输出完成战斗。

### 4.3 专属技能

| ID | 技能 | 作用 |
|---|---|---|
| `255` | 熔核鳞相 | 进入熔核形态 |
| `256` | 熔岩吐息 | 群体火焰伤害与燃烧 |
| `257` | 焦鳞缠绕 | 单体火焰伤害与敏捷下降 |
| `258` | 过热脉冲 | 火焰伤害并强化攻击或智力 |
| `259` | 蒸汽蜕鳞 | 冰弱点命中后的强制形态事件 |
| `260` | 高压蒸汽 | 群体低伤害与致盲或敏捷下降 |
| `261` | 雾障 | 提升闪避并获得一回合冰无效 |
| `262` | 雷鸣崩解 | 雷弱点命中后的崩解事件 |
| `263` | 熔核爆裂 | 蓄力一回合后的高威力群攻 |

`255 / 259 / 262` 是阶段事件，不进入常规效用候选池。

## 5. 第二关：永冻巨兽

**敌人：** `101 / 102 / 103`  
**建议等级：** 35  
**编队：** Boss + 两类随从  
**时间压力：** 第八回合后轻度软狂暴

永冻巨兽保留原型的弱火、物理无效、风反射和冰吸收。

- **永冻巨兽：** 主要伤害与群体冻结压力。
- **寒霜棱晶：** 周期蓄力群体攻击，并为巨兽提供恢复或屏障。
- **冻甲守兽：** 保护低生命单位，提高防御，并反击攻击棱晶的角色。

玩家可先击破棱晶解除倒计时，先击破守兽获得安全输出环境，或直接抢攻具有随从减伤的巨兽。巨兽降至 60% HP 后强化随从并改变保护目标。首批随从全部倒下后，巨兽只召回一种；召回类型取决于玩家先击破的目标。

## 6. 第三关：腐冠圣女

**敌人：** `104`  
**建议等级：** 50  
**编队：** 单体 Boss  
**时间压力：** 第十回合后缩短循环

战斗按“播种 → 滋长 → 收割”循环：

1. 播种直接施加现有 `ailment` 或 `dot` 状态。
2. 滋长根据玩家身上的异常数量追加属性下降。
3. 收割根据异常数量造成伤害并恢复 Boss。

本战不新增“腐种”状态。燃烧、中毒、封技、致盲、睡眠和麻痹等现有异常直接作为腐种。玩家可解除异常、使用异常盾、在收割前叠加 Boss 属性减益，或在 Boss 身上维持燃烧或中毒造成反噬。

- 65% HP：一次播种增加目标。
- 35% HP：周期性清除自身减益，并将其转化为对应强化。
- 第十回合后：日志预告“花期缩短”，部分循环跳过滋长。

| `276` | 毒蕊 | 单体伤害与中毒 |
| `277` | 噤声花粉 | 群体低伤害与封技或致盲 |
| `278` | 恶意滋长 | 按异常数量追加属性下降 |
| `279` | 丰饶收割 | 按异常数量造成伤害并恢复 |
| `280` | 枯败收割 | 足够减益下替代丰饶收割 |
| `281` | 逆植王冠 | 清除减益并转为对应强化 |
| `282` | 病花盛放 | 阶段转换时扩大异常压力 |
| `283` | 早熟花期 | 缩短播种到收割的间隔 |

## 7. 第四关：回声猎手

**敌人：** `105`

## 8. 第五关：混乱玩偶拼凑体

**敌人：** `106`  
**建议等级：** 90  
**编队：** 单体 Boss  
**时间压力：** 第三阶段四回合硬性处决

玩偶是单一战斗单位，不增加部位选择 UI。三个部件以公开完整度表现：

- 物理类别伤害削弱刃肢。
- 魔法类别伤害削弱咒眼，包括魔法类别的万能技能。
- 成功施加属性减益削弱缝合核。

第一阶段结束时，完整度最低的部件永久崩坏。同值按固定优先级 `刃肢 → 咒眼 → 缝合核` 处理。第二阶段使用剩余两个部件组合技能；第三阶段不再恢复，每回合提高伤害并降低自身防御，四回合后处决。

### 8.1 组合结果

- 崩坏刃肢：保留咒眼 + 缝合核，魔法和恢复压力更强。
- 崩坏咒眼：保留缝合核 + 刃肢，物理追击更强。
- 崩坏缝合核：保留刃肢 + 咒眼，失去恢复但获得更高攻击力。

## 9. 隐藏挑战：阳炎与大地

**敌人：** `107 / 108`  
**建议等级：** 99  
**编队：** 双 Boss  
**抗性：** 物理、枪击、火、冰、雷、风、土、光、暗、万能全部耐性

阳炎的魔法少女负责高速输出、追击与条件反击；大地的魔法少女负责恢复、强化、减益、控制和复活。两者使用独立 HP，共享主阶段。

共享生命比例为“两者当前 HP 总和 ÷ 两者最大 HP 总和”。阶段只前进不回退，恢复或复活不会令阶段倒退。

### 9.1 主阶段

#### 第一阶段：并肩试炼（100%–70%）

- 展示基础技能、协同追击和第一组公开戒律。
- 阳炎优先攻击低生命或被大地减益的目标。
- 大地维持防御、减益玩家并保护阳炎。

#### 第二阶段：天地交灼（70%–35%）

- 解锁完整戒律和连携技。
- 开启周期性小 DPS 检定。
- 强化两人的目标协同和解除能力。

#### 第三阶段：终末地平（35% 以下）

- 解锁最高级专属技能。
- 任意一方低于自身 20% HP 时，永久进入自身危急状态。
- 两者都进入过危急状态后，启动一次六个玩家回合的最终处决倒计时。
- 倒计时结束时仍未同步击破，则发动终结连携。

### 9.2 循环大 DPS 检定

- 从战斗开始持续存在。
- 第 `1–8`、`9–16`、`17–24` 等完整回合分别构成独立窗口。
- 每个窗口要求玩家方对两名 Boss 合计造成至少 `2000` 点实际 HP 伤害。
- 新窗口开始时归零，不结转溢出伤害。
- 玩家直接伤害和由玩家施加的持续伤害均计入；过量伤害只按实际 HP 损失计入；反射、自伤和 Boss 间伤害不计入。
- Boss 的恢复不会扣减已累计的伤害。
- 窗口结束时不足 `2000`，立即发动“终景·焦土无生”，显示全体 `9999` 伤害并强制判定玩家败北。该处决忽略防御、护盾、抗性、防御行动和保命被动。

### 9.3 第二阶段小 DPS 检定

- 进入第二阶段时开启，此后在第二阶段内每四个完整回合再次开启。
- 两个玩家回合内要求造成至少 `800` 点实际 HP 伤害。
- 伤害同时计入当前大 DPS 窗口。
- 成功后，大地获得一回合防御下降。
- 失败后，两名 Boss 各恢复 10% 最大 HP，并获得攻击与智力强化。

大、小 DPS 检定和最终倒计时可同时存在；任意硬性处决条件先到期即执行。

### 9.4 同步击破与复活

- 任意一方倒下后，存活者的下一次实际行动固定执行“复苏脉动”。
- 复活占用正常行动，使倒下者恢复 50% 最大 HP。
- 异常或行动延迟可推迟存活者的实际行动。
- 强制复活优先于阶段事件、戒律反击和常规行动。
- 已登记的戒律反击在复活后保留。
- 双方在复活执行前均倒下，立即胜利。
- 同一群体技能同时击倒双方，立即胜利。

### 9.5 递增异常抗性

抗性按“Boss 实例 + 异常类型”独立累计。每次成功施加某种异常后，该目标后续受到同种异常的有效命中率降低 25 个百分点，最低保留 5% 命中率。失败施加不增加抗性，解除、自然结束和复活不重置累计值。

### 9.6 公开戒律

违规会登记公开的待执行反击。对应 Boss 的下一次正常行动被反击替换；复活和阶段强制行动优先，反击顺延。

#### 阳炎的戒律

- **复燃之戒：** 同一个技能 ID 在一个玩家回合内使用三次或以上。登记“焚式复写”，对使用者发动多段攻击并附加防御下降。
- **退缩之戒：** 同一玩家回合内至少两名可行动角色选择防御或跳过。登记“逐怯阳炎”，对全队造成高伤害并追击防御或跳过者。

#### 大地的戒律

- **盈满之戒：** 任意玩家角色的正面属性等级合计达到六层或以上。登记“万象归土”，清除其全部属性强化并施加防御下降。
- **泛滥之戒：** 一个玩家回合内的实际 HP 恢复量超过全队合计最大 HP 的 30%。登记“地脉枯竭”，造成群体土伤害并降低下一回合治疗量。

每名 Boss 同时只登记一项反击；同时违反多条时按界面显示的固定顺序选择。阶段可提高反击威力，但不改变触发条件。

## 11. 校验与运行时错误处理

启动时必须校验：

- 两个 JSONL 文件不存在重复 ID。
- 自由练习排除数值 ID `>= 100` 的敌人。
- 挑战目录引用的敌人、技能和物品全部存在。
- `bossProfileId` 能在 Registry 中找到。
- Profile 强制技能属于对应敌人的可用技能集合。
- 数值 ID `>= 255` 的技能不进入任何玩家技能来源。
- 五个正常挑战顺序固定，隐藏挑战受谜题解锁状态控制。
- 隐藏挑战同时包含敌人 `107` 与 `108`。

Profile 缺失或配置错误时，对应挑战在目录加载阶段报告配置错误且不进入战斗。强制行动没有合法目标时先检查胜负；战斗未结束则记录结构化错误并跳过行动。每次行动最多发生一次阶段迁移，Orchestrator 设定最大决策步数，防止事件循环。

训练战运行状态损坏时，结束训练会话并恢复进入训练前的正式快照。奖励发放使用领取记录和事务，防止刷新或重复结算造成重复领取。

## 12. 测试与平衡

### 12.1 单元测试

- 阶段边界、不可回退和一次性事件。
- 技能优先级、冷却和固定种子效用选择。
- 戒律触发、登记、顺延和反击执行。
- 异常抗性递增及复活后保留。
- 回声只读取已完成行动。
- 玩偶完整度换算、组合和同值优先级。
- 大、小 DPS 窗口和累计伤害归属。
- 奖励单次领取和内容编号边界。

### 12.2 隐藏 Boss 边界测试

- 八回合累计 `1999` 伤害时执行全体 9999 处决。
- 八回合累计 `2000` 伤害时通过并建立新窗口。
- 小 DPS 检定伤害同时计入大窗口。
- 复活优先于待执行戒律反击。
- 异常导致存活者失去行动时，复活延后。
- 同一技能或连续行动同步击倒双方时立即胜利。
- 复活恢复 50% 最大 HP，且阶段和异常抗性不回退。
- 两名 Boss 对万能在内的全部伤害属性均为耐性。
- 9999 处决绕过所有防护与保命效果。

### 12.3 集成与模拟

建立爆发、均衡、控制和耐久四类固定玩家队伍模板，使用多个固定种子批量运行。前五关至少各保留两种稳定通关路线。退出训练、战败、刷新和奖励领取均不得污染进入训练前的正式战斗资源。

数值初始基准为本设计中的阈值；平衡阶段通过模拟调整技能倍率、HP、防御和检定数值，同时保持已确认的机制、公开规则和目标通关率不变。
### 12.4 数值锁定范围

本规格不锁定敌人的最终 HP、攻击、防御、敏捷、智力，也不锁定普通伤害技能的最终威力、命中率和异常概率。这些数值按以下流程确定：

1. 依据现有普通敌人的等级曲线外推同等级基准。
2. 根据 Boss 职能应用初始角色倾向，例如输出者提高攻击与敏捷，支援者提高防御与智力。
3. 使用爆发、均衡、控制和耐久四类队伍执行固定种子批量模拟。
4. 优先调整 HP、技能威力、冷却和异常概率；机制触发条件只在违反目标通关率时调整。
5. 达到本规格约定的通关率后，将校准结果写入 JSONL 与 Boss Profile 测试夹具。

`2000 / 8 回合` 的循环大 DPS 检定、第二阶段 `800 / 2 玩家回合` 的小 DPS 检定、同步复活的 50% HP，以及两个最终倒计时属于已锁定规则，不随普通倍率校准自动变化。若模拟证明这些规则本身造成目标通关率不可达，需要回到设计评审，而不是在实现中静默修改。
## 13. 悬浮战斗播报窗

当前 `BattleOverlay` 没有实时战斗播报区域，且现有全屏 HUD 很难在不改变布局的前提下再划分固定区域。战斗播报采用独立、可拖动、可缩放、可最小化的悬浮窗，不参与 BattleOverlay 布局。

### 13.1 组件与渲染边界

- 新建 `BattleBroadcastWindow.vue`。
- 组件由 `BattleOverlay` 控制生命周期，通过 Vue `Teleport` 渲染到 `body`。
- 战斗准备阶段不显示；进入正式战斗后显示。
- 战斗结果阶段继续保留完整播报。
- 关闭战斗结果或退出战斗后销毁组件并清空本场日志。
- 普通战斗和训练场战斗都默认显示。
- 悬浮窗层级高于战斗 HUD，低于确认、退出等模态对话框。

该组件只读取并展示结构化日志，不从文本重新推导战斗结果，也不直接参与战斗结算。

### 13.2 展开窗口

- 默认位于视口左上角。
- 默认尺寸为 `380 × 320px`。
- 标题栏是拖动区域，正文、滚动区和按钮不触发拖动。
- 右下角提供缩放手柄。
- 最小尺寸为 `280 × 180px`。
- 最大尺寸为 `720 × 70vh`，且最终尺寸不得超出当前视口。
- 拖动和缩放统一使用 Pointer Events 与 pointer capture，兼容鼠标和触摸。
- 位置与尺寸变化期间保持至少标题栏或最小化图标处于可见区域。

### 13.3 半透明视觉

- 展开窗使用约 82% 不透明度的当前主题背景。
- 使用轻度背景模糊、细边框和阴影区分悬浮层级。
- 日志文字区域必须保持可读对比度，不受战场明暗变化显著影响。
- 浏览器不支持 `backdrop-filter` 时，回退到更高不透明度的纯色背景。
- 最小化图标使用接近实色的背景，避免与战场内容混淆。

### 13.4 最小化

- 最小化后只保留一个可拖动的播报图标。
- 图标显示未读数字徽标。
- 点击图标恢复展开窗口。
- 最小化不会暂停日志收集。
- 图标位置与展开窗口位置使用同一套视口边界校正逻辑。

### 13.5 滚动与未读

- 新日志到达时不自动改变滚动位置。
- 每条新日志增加未读计数。
- 提供“跳到最新”按钮。
- 玩家主动滚动到底部或点击“跳到最新”后清除未读计数。
- 切换精简/详细模式不改变滚动位置，也不删除日志。

### 13.6 显示密度

所有战斗默认使用精简模式。玩家选择的模式跨战斗持久化。

精简模式显示：

- 技能或行动使用。
- 合计伤害、关键恢复和击倒。
- 弱点、无效、反射和吸收等关键属性结果。
- 阶段变化、戒律、DPS 检定、复活和处决倒计时。
- 战斗胜负。

详细模式额外显示：

- 每个目标与每段伤害。
- 命中、闪避和暴击。
- 属性倍率结果。
- 状态施加、失败、持续和解除。
- HP/MP 恢复。
- Press Turn 结算前后变化。
- Boss 决策树生成的公开机制线索。

详细数据在结算时始终生成，显示模式只影响渲染密度。

### 13.7 偏好持久化

使用版本化的本地 UI 偏好记录保存：

- 展开位置。
- 展开尺寸。
- 最小化状态。
- 精简/详细模式。

偏好跨战斗和页面刷新保留，不进入正式游戏存档。偏好恢复后若位置或尺寸超出视口，自动夹回可见区域。浏览器缩放、旋转和窗口尺寸变化后重新执行校正。

本地偏好缺失、版本不兼容或 JSON 损坏时，恢复默认左上角位置、默认尺寸、展开状态和精简模式。

### 13.8 播放节奏

本功能维持当前敌方回合的同步批量结算：

- 玩家行动完成后立即追加该行动的播报。
- 敌方完整回合结算后，一次性追加该回合的全部播报。
- 不引入行动间动画等待。
- 不改变 Press Turn、敌方回合或训练战状态机节奏。

这里的“实时”指悬浮窗直接响应每次战斗快照提交；敌方批量结算仍对应一次快照提交。

### 13.9 结构化日志

现有 `BattleLogEntry` 扩展为：

```ts
interface BattleLogEntry {
  id: string;
  sequence: number;
  turnCount: number;
  side: CombatantSide | "system";
  kind:
    | "action"
    | "damage"
    | "status"
    | "press_turn"
    | "mechanic"
    | "result"
    | "system";
  visibility: "both" | "detail";
  actorId?: string;
  actionId?: string;
  targetIds?: string[];
  summary: string;
  details?: string[];
}
```

- `battleLogger` 根据结算结果生成摘要和详细行。
- UI 只负责展示，不解析 `summary` 文本。
- Boss Mechanic Module 直接生成 `kind: "mechanic"` 的条目。
- `sequence` 在单场战斗内严格递增，日志 ID 必须唯一。
- 一个行动或机制事件对应一个顶层条目；多段伤害放入 `details`。
- 单场最多保留 1000 个顶层条目；超过后裁剪最旧条目，并在顶部显示“较早播报已省略”。
- 旧快照缺少新字段时仍显示既有 `summary`，保证兼容。

### 13.10 可访问性

- 展开窗使用 `role="complementary"`，日志区域使用 `role="log"`。
- 独立 `aria-live="polite"` 区域只播报关键事件，避免详细伤害持续打断屏幕阅读器。
- 最小化、恢复、模式切换和跳到最新使用原生按钮。
- 标题栏可聚焦；方向键移动窗口，`Shift + 方向键` 加速移动。
- 缩放手柄提供可读标签和键盘尺寸调整能力。
- 新日志不抢夺焦点。
- 玩家、敌人和机制的视觉区分同时使用文字标签或图标，不只依赖颜色。

### 13.11 隔离与异常处理

- 拖动、缩放或偏好持久化错误只影响悬浮窗，不中断战斗结算。
- 不支持背景模糊时仅切换视觉回退，不改变组件结构。
- 日志裁剪不影响 BattleSnapshot 中的参与者、阶段、Boss 状态或战斗结果。
- 关闭当前战斗会清空日志，但保留窗口 UI 偏好。

### 13.12 测试要求

#### 数据与日志

- `sequence` 单调递增，日志 ID 唯一。
- 玩家行动、敌方批量回合、状态、Press Turn 和结果生成正确条目。
- Boss 阶段、戒律、DPS 检定、复活和处决生成机制条目。
- 精简与详细模式展示同一底层数据的不同密度。
- 超过 1000 条时正确裁剪并显示提示。

#### 窗口行为

- 默认左上角、`380 × 320px`、展开和精简模式。
- 拖动只由标题栏触发。
- 缩放遵守最小、最大与视口边界。
- 最小化后只保留图标与未读徽标。
- 新日志不自动滚动并正确累计未读数。
- 跳到最新和滚动到底部清除未读。
- 位置、尺寸、最小化状态和模式跨战斗恢复。
- 视口缩小后窗口重新进入可见区域。
- 结果阶段保留日志，关闭战斗后清空。

#### 集成回归

- Teleport 悬浮窗不改变 BattleOverlay 的网格和尺寸。
- 悬浮窗位于战斗 HUD 之上、确认模态框之下。
- 普通战斗和训练战均显示。
- 敌方回合继续批量结算，状态机与 Press Turn 节奏不变。
- 退出训练仍恢复正式快照，悬浮窗 UI 偏好继续保留。
